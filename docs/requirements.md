# WorkCode 插件版 — 需求文档

版本：v0.1（MVP）
定位：基于 VS Code 插件的编程 Agent，对标 Claude Code
原则：插件轻、服务重；先跑通闭环，再谈扩展

## 1. 产品定位

WorkCode 是一个 VS Code 插件形态的编程 Agent。用户装官方 VS Code，再装 WorkCode 插件，即可获得 AI 对话、代码理解、代码修改、命令执行的能力。

**核心价值**：让用户不换编辑器，就能获得 Cursor / Claude Code 式的 Agent 编程体验。

**未来演进**：Agent 核心逻辑放在独立本地服务中，未来可平滑迁移到 Fork Code-OSS 的独立桌面版。

## 2. 目标用户

- 已在用 VS Code 的开发者
- 想用 AI 改代码但不想换编辑器的用户
- 需要 Agent 帮忙读代码、写代码、跑验证的开发者

## 3. MVP 能力清单

| # | 能力 | 优先级 |
|---|------|--------|
| 1 | 基于 VS Code 插件 | P0 |
| 2 | 支持打开项目和浏览文件 | P0 |
| 3 | 提供 AI 对话面板 | P0 |
| 4 | 支持将当前文件或选中代码发送给 Agent | P0 |
| 5 | Agent 能够解释代码、生成代码和修改建议 | P0 |
| 6 | 支持以 Diff 形式预览修改 | P0 |
| 7 | 用户确认后应用代码修改 | P0 |
| 8 | 支持基本的代码验证或运行命令 | P1 |

## 4. 用户故事

- 作为开发者，我打开项目，在侧边栏提问，Agent 能解释当前选中的代码。
- 作为开发者，我选中一段代码，让 Agent 改写，它以 Diff 展示建议。
- 作为开发者，我看到 Diff 后点接受，修改被应用到真实文件。
- 作为开发者，我让 Agent 改完代码后跑测试，Agent 执行命令并把结果告诉我。
- 作为开发者，我用 @ 引用另一个文件，Agent 能读到它。
- 作为开发者，Agent 要执行危险命令时，弹确认框让我决定。

## 5. 非功能需求

| 维度 | 要求 |
|------|------|
| 响应速度 | 首 token 延迟 < 3s，流式输出 |
| 安全 | 危险命令必须拦截，写操作必须确认 |
| 隐私 | 代码上下文只发给用户配置的模型 API |
| 稳定性 | 单会话不崩溃，工具失败有提示 |
| 可扩展 | 工具、模型可插拔 |

## 6. 不在 MVP 范围内

多模型路由、MCP 协议、多文件批量编辑、沙箱隔离、会话云同步、团队协作、Fork 桌面版。
